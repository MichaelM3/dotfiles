# Triage

## Context

Follow `/home/unbalanced/.agents/instructions/project-artifacts.md`. Read tracker config, labels, domain docs, ADRs, and out-of-scope notes before posting or changing state. If tracker config is missing, ask which tracker/workflow to use.

Every posted issue/comment starts with:

```markdown
> *This was generated by AI during triage.*
```

## States

Use exactly one category (`bug` or `enhancement`) and one state:

- `needs-triage`: not evaluated.
- `needs-info`: blocked on reporter/user detail.
- `ready-for-agent`: enough context, acceptance criteria, and verification for AFK work.
- `ready-for-human`: product/design/access/judgment required.
- `wontfix`: duplicate, out of scope, invalid, or not worth doing now.

Use `.agents/triage-labels.md` mapping when present.

## Workflow

1. Read full issue, comments, labels, linked PRs, and prior triage notes.
2. Inspect relevant code/docs. For bugs, attempt reproduction before asking product questions.
3. Summarize understanding, likely area, missing facts.
4. Recommend one state with reasoning.
5. If decisions are missing, use `grilling` and `domain-modeling`, or
   `grill-with-docs` when the user wants the combined flow.
6. Apply outcome through the configured tracker.

## Outcome Actions

- `ready-for-agent`: post brief using `references/AGENT-BRIEF.md`.
- `ready-for-human`: same brief, with why delegation is unsafe.
- `needs-info`: post specific questions.
- `wontfix` enhancement: optionally update `.agents/out-of-scope/` using `references/OUT-OF-SCOPE.md`, then close/mark done.
- `wontfix` bug: explain and close/mark done.

## Ready-for-Agent Checklist

- Expected/current behavior clear.
- Repro steps or implementation goal concrete.
- Relevant files/search terms included.
- Acceptance criteria testable.
- Verification commands listed.
- Dependencies and out-of-scope explicit.

## Attention Buckets

Oldest first: unlabeled/uncategorized, `needs-triage`, then `needs-info` with new reporter/user activity.
